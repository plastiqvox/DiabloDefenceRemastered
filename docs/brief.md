# Diablo Defence Remastered — 요구사항 메모

기획·설계·구현·검증 담당이 함께 보는 출발점이다. 사실(원작 분석)과 사용자 요구를 적는다.
결정은 `docs/gdd.md`(기획), `docs/architecture.md`(설계)에서 한다.

## 1. 배경

- 원작: 2011년에 만든 C# WinForms 게임 "DiabloDefence". 디아블로 1 그림 자원을 가져와 만든 개인 프로젝트.
  원본 소스는 `G:\Workspace\DiabloDefence\` 에 그대로 있다(참고용, 고치지 않는다).
  - 원작 구조: `CUnit.cs`(2200줄, 유닛 종류마다 if/else), `CPathFinder.cs`(A* 아님 — 방향 우선 탐욕 탐색),
    `CMissile.cs`, `CItem.cs`, `MainForm.cs`(60ms WinForms 타이머 한 개로 갱신과 그리기를 같이 함).
  - 원작 문제: 정수 픽셀 좌표·틱 단위 속도, 갱신/그리기 결합(그리기 함수 안에서 애니메이션·상태가 바뀜),
    Y 좌표마다 전체 유닛을 도는 그리기 정렬, 충돌 정보 없는 맵, 유닛 종류별 복붙 코드.
- 이 저장소(`G:\Workspace\DiabloDefenceRemastered`)는 **새로 설계해서 다시 만드는 프로젝트**다.
  옛 코드를 복사해 오지 않는다. 그림 자원만 `src/DiabloDefenceRemastered/Assets/` 에 PNG(무손실 변환)로 있다.
- **저장소는 GitHub 공개 저장소**(plastiqvox/DiabloDefenceRemastered)다. 그림 자원은 저작물이라 git 에 넣지 않는다
  (`.gitignore`). 클론 뒤 `tools/import-assets.ps1` 로 원작 exe 에서 꺼내 채운다. 빌드는 Assets 가 비어 있으면 알기 쉬운 오류를 내야 한다.
- (2026-10-30 추가) 사용자가 **디아블로 1 원본 데이터**를 가지고 있다: `G:\Workspace\Diablo (devilutionx)\Diablo (devilutionx)\diabdat.mpq`
  (DevilutionX 설치본, `hellfire*.mpq` 도 있음). 여기서 소리·몬스터·마법 효과·배경을 가져와 쓰기로 했다(요구 10, 사실은 8절).
  이것도 Blizzard 저작물이라 저장소에 넣지 않고, 가져오기 도구가 사용자 PC 에서 뽑아 `Assets/` 에 채운다. 원본 폴더는 읽기만 한다.

## 2. 사용자 요구 (대화에서 받은 그대로 정리)

1. 유닛이 제대로 된 길찾기로 움직일 것. 처음 요청은 "A* 로". 이후 장르가 바뀌어서
   **무리(horde)는 플로우 필드, 보스·정예·아군 같은 개별 유닛은 A*** 를 기본안으로 한다(설계에서 확정).
2. 픽셀 단위 이동·계산을 **게임에서 정석인 방식**으로: 실수 좌표, 초당 속도 × dt, 고정 틱 시뮬레이션 + 보간 렌더,
   원 충돌·분리(steering), 공간 분할 질의 등.
3. 배경 그래픽에 **벽·장애물을 그려 넣어도 된다. 배경과 어울리게** 그릴 것(돌 질감·그림자·높이감).
   장애물 정의 하나로 그림과 충돌 정보를 함께 만든다(그림과 충돌이 어긋나지 않게).
4. **현세대 프로젝트로 새로 만들 것.** 이름은 "Diablo Defence Remastered". "요즘 게임처럼".
5. **옛 코드를 그대로 가져와 쓰지 말고, 괜찮은 디자인 패턴을 적용해 구현**할 것.
6. 나중에 **스테이지, 적, 마법 이펙트, 스킬을 확장**할 수 있는 설계(데이터 정의 추가로 늘어나게).
7. **뱀파이어 서바이버즈 같은 방식**: 이동 위주 조작 + 자동 공격, 몰려오는 적 무리, 경험치, 레벨업 때 강화 선택, 생존 시간.
8. **몬스터 종류를 늘릴 것.** 새 그림은 없으므로 원작 디아블로처럼 색 바꾸기·크기·행동 변형(돌진, 자폭, 원거리 시전,
   분열, 정예/챔피언 무리 등)으로 늘린다. (요구 10 이후로는 원작 디아블로 1 의 몬스터 그림 묶음과 색 변종(TRN)이 먼저다)
9. 기획·설계·구현·검증 네 역할이 서로 리뷰하며 만든다.
10. (2026-10-30, 사용자 승인) **디아블로 1 원본 자원을 쓸 것**: 사용자가 가진 `diabdat.mpq` 에서 **소리(효과음·음악), 몬스터, 마법 효과,
    배경(던전 타일 맵)** 을 가져온다. 자원은 저장소에 넣지 않고(공개 저장소, Blizzard 저작물) 가져오기 도구가 사용자 PC 에서 뽑는다.
    → 기획서 v0.4(19절 자원 원칙, 8~10절 몬스터·보스·아레나, 12.7 소리)에서 받았다.

## 3. 기술 결정 (확정)

- .NET 9 (`net9.0`), **MonoGame 3.8.6 DesktopGL** (`MonoGame.Framework.DesktopGL`), 글꼴은 **FontStashSharp.MonoGame 1.6.2**
  (런타임 TTF. 한글은 Windows 의 `C:\Windows\Fonts\malgun.ttf` 를 쓰고, 없으면 대체 글꼴).
- 콘텐츠 파이프라인(MGCB) 은 쓰지 않는다. `Texture2D.FromFile`/`FromStream` 으로 PNG 를 바로 읽는다.
- 테스트: xUnit 프로젝트(`tests/`). 길찾기·플로우 필드·데이터 정의 검증 같은 순수 로직을 테스트한다.
- NuGet 은 이 PC 에서 받을 수 있다(확인함).
- 빌드 도구: `dotnet` SDK 9.0.306.
- 주석·문서는 한국어. 커밋은 메인 세션이 한다(역할 에이전트는 커밋하지 않는다).

## 4. 그림 자원 (src/DiabloDefenceRemastered/Assets)

원작 exe 에서 꺼낸 PNG 49장이다. 요구 10 이후 몬스터·주인공·마법·맵은 디아블로 1 원본(8절)으로 바꾸고,
이 표의 자원은 아이콘·획득물·타이틀·로고·커서에만 계속 쓴다(기획서 19.3).

투명색: 유닛·미사일·아이템 시트는 **순수 검정 (0,0,0)** 이 투명. `LOGO` 는 **(0,255,0)** 이 투명.
읽을 때 투명색을 알파 0 으로 바꿔 premultiplied 로 올린다.

방향: 시트의 **열 = 방향, 행 = 프레임**. 12방향 시트에서 열 번호 = round(angle / 30) mod 12,
angle 은 **남쪽 0°, 서쪽 90°, 북쪽 180°, 동쪽 270°** (화면 좌표 y 아래 방향, `angle = atan2(-dx, dy)` 를 0..360 으로).
16방향 시트(미사일)는 22.5° 단위로 같은 기준. ※ 원작 코드에서 읽은 규칙이라 실제 그림으로 한 번 확인할 것.

(요구 10 이후 기획서 v0.4 는 이 맵을 쓰지 않고 디아블로 1 던전 타일로 만든 아레나를 쓴다 — 기획서 10.1. 아래는 원작 맵 기록으로 남긴다.)

탁 트인 안뜰. 원작에는 충돌 정보가 전혀 없었다. 그림에서 읽은 것:

  - 위쪽 오른편 덤불 띠: 다각형 (880,0) (1190,0) (1190,95) (960,100) (880,45)

## 7. 지켜야 할 것

- 상표 로고를 본뜬 그림을 새로 만들지 않는다(기존 자원은 사용자 개인 자원으로 그대로 쓴다).
- 검증은 사용자 화면을 건드리지 않고 한다. **화면 캡처(CopyFromScreen)·마우스/키 입력 주입 금지.**
  대신 게임에 개발용 실행 옵션을 둔다(예: `--autoplay` 자동 조작, `--capture <png> --capture-at <초>` 로
  게임 렌더 타깃을 파일로 저장, `--quit-after <초>`, `--seed`). 창은 잠깐 떠도 되지만 앞으로 끌어오지 않는다.
- 저장소 밖 파일을 고치지 않는다.
- 디아블로 1 원본 폴더(`G:\Workspace\Diablo (devilutionx)\...`)는 읽기만 한다. 디아블로·DevilutionX 를 실행하지 않는다.
  원본에서 뽑은 그림·소리·맵을 저장소에 넣지 않는다(git 제외인 `Assets/` 에만).
  원작 그림이 찍힌 게임 캡처·가져오기 견본 그림·원작 형식 파일(`*.pal`·`*.trn`·`*.min`·`*.til`·`*.sol`·`*.dun` 등)도 저장소 밖(작업용 임시 폴더)에 둔다(기획 19.1).

## 8. 디아블로 1 원본 자원 (사실, 2026-10-30 조사)

조사 문서: 세션 스크래치의 `diablo-inv/inventory-sprites-sounds.md`(몬스터·마법·주인공·소리), `diablo-inv/inventory-levels.md`(던전 타일).
변환 시제품(`d1conv`, `d1map`)이 아래 형식을 실제로 PNG 로 풀어 색·투명·방향 순서·타일 맞물림을 눈으로 확인했다. 게임 화면에 올려 보지는 않았다.

- **원본 파일**: `diabdat.mpq`(517MB, 기본), `hellfire.mpq`·`hfmonk.mpq`·`hfmusic.mpq`·`hfvoice.mpq`(헬파이어 확장), `devilutionx.mpq`(옛 판 — 표·경기장 DUN 이 없다).
  MPQ 에 파일 목록이 없어 이름을 바깥(실행 파일 문자열·체험판 목록·DevilutionX 공개 소스)에서 모아 하나씩 확인했다(3781 후보 중 3508 개 있음).
- **읽기**: War3Net.IO.Mpq(MIT) 로 열린다. 경로 구분자는 `\`, 대소문자 무관.
- **몬스터**: diabdat 에 그림 묶음 34개(일반 22 + 보스 해골왕 `sking`·도살자 `fatc`·디아블로 `diablo`). 원작 112종 중 일반 등장 88종(이름 중복 빼면 77종).
  동작 n 서기·w 걷기·a 공격·h 맞기·d 죽기·s 특수, **모두 8방향(S, SW, W, NW, N, NE, E, SE)** — 4절 각도 규칙(남 0°, 서 90° …)에서 45° 단위 열 순서와 같다.
  색 변종 TRN 110개(고유 몬스터용 31개 `monsters\monsters\*.trn`). 헬파이어 몬스터 26종(선택).
- **마법 효과**: `missiles\` 316개. 파이어볼·성스러운 화살 16방향 14프레임(파일 하나가 방향 하나, 1번 = 아래, 시계 방향), 뼈 영혼·엘리멘탈 8방향,
  번개·노바·화염벽은 방향 없음. 화살 `arrows.cl2` 는 프레임 번호가 방향.
- **주인공**: 전사·도적·마법사 각 255개 그림(직업 × 갑옷 3 × 무기 9 × 동작), 수도사(헬파이어). 합 174MB.
- **소리**: 모두 PCM WAV, 대부분 모노 8비트 22050Hz. 효과음 1049개 223MB(그중 마을 사람 대사 374개 126MB), 몬스터 소리 378개, 음악 8곡
  (`dintro` 첫 화면, `dtowne` 마을, `dlvla~d` 대성당·지하묘지·동굴·지옥, 헬파이어 `dlvle`·`dlvlf`). 게임 라이브러리가 8비트 WAV 를 읽는지는 확인하지 않았다.
- **배경(타일)**: 층마다 `CEL`(32×32 조각) · `MIN`(하위 타일 = 조각 기둥) · `TIL`(메가타일 = 하위 타일 2×2) · `SOL`(칸마다 걷기·투사체·시야 막힘 비트) · 팔레트.
  마을·대성당 L1·지하묘지 L2·동굴 L3·지옥 L4. 미리 만든 방 DUN 44개(해골왕 방, 도살자 방 등). 화면에서 하위 타일 한 칸 = 64×32 마름모.
  무작위 생성기 없이 메가타일 번호를 손으로 깔아 넓은 대성당 방(하위 타일 40×40)을 원작과 똑같이 그릴 수 있었다.
- **형식 함정(요약)**: 그림자는 투명이 아니라 색인 0(불투명 검정)이다. 스프라이트는 팔레트 하나(`l1.pal`)로 다 풀린다. 프레임 폭이 파일에 없다(추정 가능).
  원본 SOL 에 틀린 값이 있다(DevilutionX 가 고치는 목록이 있음). 막힌 흙 칸 그림은 32px 떠 보인다. 넓은 바닥을 한 장으로 구우면 텍스처 크기 2048 을 넘는다.
- **L1 둘레 조각의 SOL**(2026-10-30 구현 담당이 diabdat 를 직접 읽어 확인): 해골왕 방 앞 둘레의 흙 턱 메가타일 18·19·20·24 는 하위 칸 4개가 모두 SOL 15
  (걷기·시야·투사체 막힘 + 투명)다. 보기에는 낮지만 걷기와 투사체를 둘 다 막는 하위 칸 두 줄 두께의 벽이다. 뒤 아치 벽(메가타일 1·2)은 한 줄만 막히고 나머지 반은 바닥이다.
