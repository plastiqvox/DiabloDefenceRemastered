## 지적 원문

### 1. (낮음, 둘 다) 그림자를 기획은 "게임이 따로", 설계는 "도구가 굽는다"

- **위치**: 기획 19.6 "그림자"·30절 새로 정한 값 표·brief 요구 16 ↔ 설계 1.4 ⑥·7.5.
- **문제**: 기획서와 brief 는 "그림자는 게임이 몸 아래에 따로 그린다" 로 적었다. 설계는 "도구가 매끈하게 늘린 그림자를 같은 시트에 굽고, 게임은 따로 그리지 않는다" 를 골랐다.
  기획 19.6 은 굽기·그리기 선택을 설계에 맡겼지만, 같은 문단과 30절 표의 문장은 "게임이 따로" 로 굳어 있다. 두 문서가 서로 다르다. 확인 항목 ④ 의 "몸과 따로 놀지 않는가" 도 굽는 방식에서는 뜻이 달라진다.
- **제안**: 기획 19.6·30절·brief 의 그림자 문장을 "가져오기가 원본 그림자를 매끈하게 2배로 늘려 시트에 굽는다(게임 그리기 경로는 그대로)" 로 맞춘다. 설계 13.20 "기획에 넘길 것" 1 에 이 항목을 분명히 적는다.

### 2. (높음, 둘 다) 들어온 문 바꾸기가 맞은편 문의 이벤트를 주인공이 들어온 문으로 옮긴다

- **위치**: 설계 3.6 결정 2 "v0.8 거울판과 문 이름"("보스 `gate_ne` … 늘 맞은편")·결정 5 `RemapEntry` / 기획 13.4·10.3 이벤트 표 10:00 보스 `entry:gate_ne`.
- **문제**: `RemapEntry` 의 "서로 바꾸기" 는 들어온 문의 맞은편 문에 적힌 이벤트를 들어온 문으로 옮긴다. 지금 코드(`RoomState.cs` 118~124)와 시험(`RoomEventsTests` 66줄 `fromSw.RemapEntry("gate_ne") == "gate_sw"`)이 이 동작을 확인한다.
  보스 방은 늘 `gate_sw` 로 들어오고(`boss_entry`) 보스 이벤트는 `entry:gate_ne` 다. 그래서 해골왕이 모든 판에서 방 시계 0:03 에 주인공이 막 들어온 문으로 나온다.
  일반·정예 방도 들어온 문이 sw 면 `gate_ne` 이벤트(2번 방 행진, 7번 방 대장, 8번 방 대장)가, se 면 `gate_nw` 이벤트(5·7·8번 방)가 주인공 문으로 온다.
  기획 13.4 "들어온 문이면 맞은편으로"(한쪽만 바꿈)의 뜻과 다르다. 그런데 설계 v0.8 은 "보스 늘 맞은편" 이라고 적어 문제를 덮고, 거울판 설명도 그 문장에 기댄다. 13.5-23 ⑤ 는 "행진 시작 문 = 목표 문" 만 보므로 이것을 못 잡는다.
- **제안**: 바꾸기 규칙을 고친다. 안 1: 이벤트 문 = 들어온 문일 때만 맞은편으로 바꾸고, 행진의 목표 문은 시작 문을 바꿨을 때만 들어온 문으로 바꾼다(쌍으로 처리). 안 2: 이벤트 문을 "기준 들어온 문(sw)에 대한 상대 문" 으로 정의하고 실제 들어온 문에 맞춰 돌린다.
  13.5-23 ⑤ 에 "바꾼 뒤 이벤트 문 = 들어온 문이면 오류"(들어올 수 있는 문마다, 거울판 포함)를 더하고, 3.6 의 "늘 맞은편" 문장은 고친 규칙으로 다시 쓴다. WP1f #8·#12 에서 시험을 고친다.

### 3. (중간, 둘 다) 끊은 판과 끊지 않은 판을 어느 틱에 견주는지 없다

- **위치**: 설계 11.1 WP1f "완료 기준 — 끊고 잇기"·3.6 결정 4 `Suspend` / 기획 15절 "판 전체 실행"·14.1 단계 3 완료 기준.
- **문제**: `Suspend` 는 `CanSuspend` 인 순간(보스 방 Doors 단계)에 방을 닫는다. 끊지 않은 판은 주인공이 계단 문 틈까지 걸어간 뒤(또는 `DOOR_SKIP`)에 닫는다.
  그래서 같은 씨앗이라도 보스 방 `RoomRecord.Ticks`·`ElapsedTicks`·짐 체력(재생)이 달라진다. 지금 "끊은 판 = 끊지 않은 판(판 해시·`RoomRecord` 목록 같음)" 기준은 어느 틱에 끊는지 정하지 않아 그대로는 맞을 수 없다.
  자동 조작 판 전체 실행(35분)에서는 "언제 `Suspend` 하나" 가 아예 없다.
- **제안**: 비교 기준을 정한다. 안 1: 시험의 (가)는 `Suspend` 한 틱과 같은 틱에 `CommandButtons.Exit(계단 문 번호)` 로 나간다. 안 2: `Suspend` 를 `Phase == Exit`(`ChosenExit` = 계단) 때도 허용해 `Advance` 자리를 그대로 대신하게 한다.
  자동 조작 판 전체 실행도 "계단 출구로 나가는 틱에 `Advance` 대신 `Suspend` → JSON → 이어 하기" 로 적는다. 기획 15절 문장도 같은 정의로 맞춘다.

### 4. (중간, 둘 다) 실제로 확대 프로그램을 띄우는 길이 시험되지 않는다

- **위치**: 설계 1.4 "시험"(`IUpscaler` 가짜)·11.1 WP0 v0.8 / 기획 19.6 "시험이 만든 가짜 확대 프로그램".
- **문제**: 설계는 확대를 `IUpscaler` 인터페이스 뒤에 두고 가짜 구현으로 시험한다. 그러면 실제로 외부 프로세스를 띄우는 길이 GPU 없는 CI 에서 하나도 시험되지 않는다:
  인자 목록(`-i`/`-o`/`-n`/`-s`/`-f`/`-g`), 셸 없이 띄우기, 종료 코드 판정, 10분 시간 초과, "`-t 128` 로 한 번 다시", 결과 파일 없음(이 프로그램은 그림 하나를 못 읽어도 종료 코드 0 으로 끝난다 — 확인 필요), 해시 확인 단계.
  기획은 "가짜 확대 프로그램"(실행 파일)을 말하므로 두 문서도 다르다. 또 해시 확인은 실제 `upscale.json` 의 공식 해시와 대조하므로, 시험이 표를 바꿔 끼울 수 없으면 가짜 프로그램은 늘 "해시 다름" 으로 되돌아간다.
- **제안**: 시험이 빌드하는 작은 가짜 콘솔 실행 파일을 둔다(최근접 4배, 인자로 "오류 종료·잠자기·출력 빼기·크기 틀림" 을 흉내 냄). 그것으로 `Process` 경로 전체를 시험하고, `IUpscaler` 가짜는 처리 ①~⑦ 단위 시험에만 쓴다.
  시험이 upscale 표(허용 해시)를 주입할 수 있게 한다. "결과 파일이 없으면 실패" 를 실패 판정에 명시한다. 모델 경로는 `-m <upscale-bin>/models` 로 넘겨 해시를 확인한 파일만 쓰게 한다(작업 폴더의 `models` 를 먼저 찾는 동작을 막음).

### 5. (중간, 둘 다) 그림자를 누가 그리는지 두 문서가 다르다 — 게임이 두 번 그릴 수 있다

- **위치**: 기획 머리말 v0.8.2 줄·19.6 "그림자"·30절 새로 정한 값·열린 질문 42, brief 요구 16 / 설계 1.4 ⑥·7.5.
- **문제**: 기획은 여러 곳에서 "게임이 몸 아래에 따로 그린다" 고 적었다(19.6 은 "도구가 굽을지는 설계" 라며 맡겼지만, 머리말·30절 표·Q42·brief 16 은 "게임이 따로" 로 굳혀 적음).
  설계는 "도구가 시트에 굽고, 게임은 따로 그리지 않는다" 로 정했다. WP5 가 기획서를 보고 그림자 그리기 경로를 따로 만들면 그림자가 두 번 그려지거나 그리기 호출이 늘어난다.
- **제안**: 기획 v0.8.2 머리말·19.6·30절 표·Q42·확인 항목 ④ 와 brief 16 을 "도구가 원본 그림자 모양을 AI 없이 매끈하게 2배로 늘려 시트에 굽는다(게임 그리기는 그대로)" 로 맞춘다. 설계 13.20 의 "기획서에 넘기는 것 1" 에 이 항목이 있으니 기획 담당이 받으면 된다.

### 6. (낮음, 기획) 동시에 고치며 남은 문구 차이 셋

- **위치**: 기획 10.8 거울판 v0.8.2 짝 후보 / 19.6 해시·적용 범위 켜고 끄기.
- **문제**: ① 기획 10.8 은 둘레의 앞 턱 18 ↔ 19·턱 모서리 23 ↔ 24 를 짝 후보로 적었다. 설계 6.11 은 둘레·문 조각은 자리로 고르므로 짝 표에 넣지 않는다(실제 `l1.json` `gates` 의 `end_b` 와 `borders` 도 변·모서리마다 따로 정함).
  ② 19.6·30절은 해시 대상을 "실행 파일·모델 두 파일" 이라 했다. 설계는 exe·`vcomp140.dll`·param·bin 넷이다(exe 가 `VCOMP140.DLL` 을 가져오므로 설계 쪽이 맞음).
  ③ 19.6 의 "가져오기 표 항목마다 켜고 끔" 과 달리 설계는 `Table/upscale.json` 의 `include`/`exclude` 를 쓴다.
- **제안**: 설계 13.20 "기획서에 넘기는 것" 1·4 대로 기획 10.8 의 18 ↔ 19·23 ↔ 24 를 "자리로 바뀜(짝 표 밖)" 으로 옮긴다. 19.6·30절 해시 대상을 "exe·DLL·모델 두 파일" 로, 항목 끄기를 "`upscale.json` `exclude` 한 줄" 로 고친다.

### 7. (낮음, 둘 다) 세로 창살의 기둥 칸 보정이 원작 수정판에 없으면 "기획 의도 차이 MVP 에 없음" 과 부딪힌다

- **위치**: 설계 6.11 짝 검사 "`sol_known_diffs` 가 있는 조각은 짝도 전치 자리에 보정"·11.1 WP0 v0.8 ③ / 기획 10.1 "기획 의도 차이 — MVP 에는 없다".
- **문제**: 창살 36 의 기둥 칸 `X` 는 DevilutionX 의 보정(조각 63)이다. 짝 검사는 세로 창살(35 후보)에도 같은 칸에 보정이 있어야 통과한다.
  그런데 DevilutionX 가 35 쪽 기둥 조각은 고치지 않는다면, 그 보정은 "DevilutionX 참고" 가 아니라 "기획 의도 차이" 가 된다. 기획 10.1 은 기획 의도 차이가 MVP 에 없다고 적었다.
  그러면 `cathedral_arena` 거울판은 원본 성질과 기획 규칙 둘 중 하나를 어기게 된다.
- **제안**: WP0 이 35 의 원본 SOL 과 DevilutionX 보정 여부를 확인하는 단계에 "보정이 없으면 `design_diffs`(이유: 거울판 짝 맞춤)로 넣는다" 는 규칙을 둔다. 기획 10.1 의 "기획 의도 차이 MVP 에 없음" 에 이 예외를 적는다. 안 넣을 거면 그 맵은 거울판을 쓰지 않는다고 적는다.
