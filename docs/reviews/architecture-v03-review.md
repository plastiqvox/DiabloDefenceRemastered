- 대상: `docs/architecture.md` v0.3(디아블로 1 원본 자원 사용 반영판), 기준 기획서 `docs/gdd.md`, WP1 코드(커밋 `ec851d6`)

## 제안과 다르게 반영한 것

- **I3 정렬 키**: 제안은 걸을 수 있는 칸의 덧그림을 `(칸 줄 tx+ty, 종류 순서)` 키로 정렬하는 것이었다. 유닛까지 칸 줄 키를 쓰면 이웃 칸에 선 두 유닛이 화면 y 와 반대 순서로 그려질 수 있어(칸 줄 ≠ 땅 깊이),
  한 키(y)를 유지하고 **덧그림이 있는 칸 안의 유닛만** 키를 `min(발 y, 칸 중심 y − 0.5)` 로 당기고 덧그림 키를 칸 중심 y 로 했다. 결과는 원작 순서(그 칸 유닛 → 덧그림 → 앞 줄 유닛)와 같다.
  뒷둘레·앞둘레를 정렬 밖 단계로 빼는 것은 제안 그대로다. 맵 밖에서 들어오는 유닛이 뒷벽 위에 그려지지 않도록 뒤쪽 바깥 입장 유닛을 뒷벽 단계 앞에 그리는 규칙을 보탰다.
- **I13 진입점 기본값**: 문 위치에서 `entries` 기본값을 계산하는 길은 두지 않았다. WP5 가 `--debug-nav entries` 로 맞추는 값이라 "칸 중심 = 정수" 규칙과 예 값(19.5)으로 충분하다.
- **V6 읽기 진입점**: 제안의 `DataLoader.LoadKinds(dir, kinds)`(WP7) 대신 Core `Map/MapDataReader`(WP1b)로 했다. WP0 이 WP7 을 기다리지 않게 하려는 구현 I1 과 같은 이유다.
  `tilesets`·`maps` 에 `extends` 를 금지해 병합 규칙이 두 벌이 될 일을 없앴고, WP7 로더도 이 두 종류는 `MapDataReader` 결과를 받는다. "두 경로의 `LayoutHash` 가 같다" 시험은 그대로 넣었다(`Integration`).
- **V9 수치를 둘 곳**: 프레임 시간·타격 프레임은 가져오기 표가 아니라 게임 정의(그림 묶음 클립)에 둔다. 타격 프레임은 게임 규칙이고 자원 없이 검사해야 하기 때문이다(설계 6.3). 기획 19.1 이 다르게 적었으면 기획 담당이 맞춘다.

## 남은 열린 질문 (기획 담당)

1. 보스·중간 보스 본체가 다른 적의 오라·함성 버프를 받는가(설계 기본: 받지 않음, `include_bosses: false`).
2. 판독성 하한: 어둠 값·주인공 빛 반경·`unit_min_light` 값(리뷰 예: 어둠 S1 0.5·S2 0.6·보스 0.7, 하한 0.6), 원거리 적 kite 띠를 빛 반경 안으로.
3. "큰 피해" 기준 숫자(`hp_pct`·`reach_over_contact`·`area`) — 정해질 때까지 검사는 경고.
4. 스테이지 2 협로·앞둘레가 높은 벽일 때 `wall_fade` 를 `hero` 로 둘지 `radius` 로 둘지(기획 열린 질문 15 와 함께).
5. 등급 배율을 곱한 최종 크기를 자를지(`rules.ranks.max_scale`), 또는 썩은 시체류를 우두머리 크기 배율에서 뺄지.
6. 원본 유래 수치를 저장소에 손으로 적는 범위를 사용자가 승인하는지(기획 열린 질문 19).
7. 기획 10.1·10.2 의 "낮은 턱은 투사체 통과" 문구 — 원본은 `X`. 앞둘레를 투사체가 넘어야 할 기획 이유가 있으면 `design_diffs` 로 적는다.

## 지적 원문

### 구현 담당

#### I1 (높음, 설계) 도구가 맵 정의를 읽을 길
- 자리: 1.4 "맵 그림은 표에 없다 — 도구가 Data/tilesets·maps 를 Core record 로 읽어 Expand", 11.1 WP0·WP7, 6.14 13.5-10, 10.1 Assets 줄
- 문제: WP0 도구는 Data/tilesets·maps JSON 을 MapDef·TilesetDef 로 읽어야 한다. 13.5-10 시험(WP0 소유)은 모든 정의가 가리키는 파일 이름을 모아야 한다. 그런데 snake_case 옵션, Vector2·Rgb 변환기, DefRef 연결(MapDef.Tileset), extends 병합은 WP7 의 DataLoader 에 있다. 전체 로더를 쓰면 다른 묶음의 부품 등록과 데이터 오류에도 걸린다. 11절 순서는 WP0 와 WP7 을 동시에 돌리고, WP0 단계 1 완료 기준에 'L1 아레나 굽기' 가 있다. 그래서 WP0 는 받은 정보만으로 끝낼 수 없다. 도구 안에서 따로 파싱하면 병합·변환 규칙이 두 벌이 되어 그림과 충돌이 다른 배치로 만들어질 위험이 생긴다.
- 제안: WP1b 에 Core 의 'Map 데이터 읽기' 하나를 넣는다(예: Map/MapDataReader.Read(dataDir) → (maps, tilesets), STJ 옵션·변환기를 Core 공용으로 옮김, tilesets·maps 종류만 읽고 tileset ID 로 연결). WP7 로더와 도구가 같은 함수를 쓰게 한다. 13.5-10 은 '정의 → 파일 이름' 추출을 WP7 로더 결과로 하므로 Integration 분류에 두고, WP0 의 자원 없는 시험은 표 → 이름 목록 쪽만 맡는다. 아니면 11절 순서에 'WP0 맵 굽기는 WP7 로더 뒤' 라고 적는다.
- 처리: 제안의 첫 길대로. `MapDataReader`(WP1b #9), 공용 `Data/Json/DefJson`(WP1b #21), 두 종류는 `extends` 금지, 13.5-10 ① 기본 ② `Integration`.

#### I2 (높음, 설계) 가져오기 표·arena.json 모양
- 자리: 1.4 가져오기 표(예는 monsters·missiles 둘), WP1b #10 ImportTable·SpriteMeta·AssetManifest, 7.6 arena.json
- 문제: WP1b 는 ImportTable 을 '구현과 시험까지' 해야 한다. 그런데 표 7개 중 hero·icons·sounds·music·exe 표의 모양이 문서에 없다. 도구가 실제로 필요한 값도 표 모양에 빠져 있다: 동작별 칸 폭(마법사 as 96 / fm·lm·qm·at 128), 표마다의 shadow_alpha(firerun·guard·주인공도 그림자가 있음), 아이콘의 (마법, 방향, 프레임), 화살 3장 겹침, optional 표시. 시제품 쓰임새를 보면 WP1b 가 추측으로 만든 형을 WP0 가 곧바로 바꿔야 한다(WP1c 행). arena.json(floor 목록·columns·cells·layout_hash·box)은 WP0 가 쓰고 WP5 렌더와 WP7 시작 검사가 읽는다. 그런데 WP1b 파일 목록에 이 형이 없다. cells 의 frame 이 0 기반인지 1 기반인지, 바닥 조각 이름과 '빈 조각' 규칙도 정해지지 않았다. 이 규칙이 없으면 시작 검사와 13.5-10 이 맵 파일 이름을 미리 알 수 없다. 타일셋의 원본 정보(l1 → levels\l1data 의 CEL/MIN/TIL/SOL/L1S 경로, 하위 타일당 조각 수 10/16, 팔레트 이름 → 파일, L1S 덧그림 번호표)도 둘 곳이 정해지지 않았다.
- 제안: WP1b 계약에 다음을 모두 적는다. 첫째, 표 7개의 JSON 모양(동작별 width 덮어쓰기, 표/항목별 shadow_alpha, icons 항목 모양, optional). 둘째, Core Assets/ArenaArt record(arena.json, cells frame 은 1 기반 등 6.1 규칙). 셋째, '바닥 조각 이름 = 바닥 칸 마름모가 걸치는 512 칸' 처럼 자원 없이 계산되는 규칙. 넷째, 타일셋 원본 정보를 Table/tilesets.json 에 둘지 도구 코드 상수로 둘지. 또는 Core ImportTable 은 '만들 이름 목록' 에 필요한 필드만 엄격히 읽고, 나머지는 도구가 따로 읽는다고 범위를 줄인다.

#### V2 (중간, 설계) --mute 와 OpenAL 장치
- 자리: architecture.md 7.9 무음, 9절 --mute, WP8 완료 기준('--mute 실행에서 장치를 열지 않음(로그)'), R21
- 문제: MonoGame DesktopGL 3.8 의 SDL 플랫폼은 Game 을 만들 때 OpenALSoundController 를 만들어 기본 오디오 장치를 연다. NuGet 의 MonoGame.Framework.dll 3.8.6 에서 'Failed to init OpenALSoundController' 와 'OpenAL device could not be initialized' 문자열을 확인했다. 그래서 '--mute 면 장치를 열지 않는다' 는 게임 코드로 지킬 수 없고, 로그로 확인할 수도 없다. 장치가 없는 PC 에서는 'NoAudioHardwareException → 무음으로 계속' 보다 앞서 new GameApp() 단계에서 예외가 날 수 있다. 또 기본이 무음이고 '파일도 읽지 않는다' 라서 SoundEffect.FromFile 로 가져온 WAV 를 실제로 읽는 길은 개발 실행에서 한 번도 돌지 않는다. 이 길을 확인하는 방법은 --sound 뿐인데 이것은 사용자 스피커로 소리를 낸다(10.2 도 '사용자 동의를 받고'). 7.9 의 '소리 켬/끔 해시 같음' 은 Core 의 Presentation.Enabled 시험으로만 확인한다. 게임 AudioSystem 이 World 를 받는 경로는 확인하지 않는다.
- 제안: 개발 옵션 실행에서는 new GameApp() 전에 환경 변수 ALSOFT_DRIVERS=null 을 둔다. MonoGame 이 함께 싣는 openal.dll(OpenAL Soft 1.24)에 'ALSOFT_DRIVERS' 와 'No Output' 문자열이 있다. SDL 힌트와 같은 방식이다. 이렇게 하면 장치는 '출력 없음' 으로 열린다. 그러면 --sound 실행도 스피커 없이 WAV 읽기·재생·제한을 끝까지 돈다. 사용자 스피커로 내는 것은 별도 옵션(예: --sound-device default)이 있을 때만 하고 동의를 받는다. 완료 기준의 '장치를 열지 않음' 은 '로그에 장치 이름 = No Output' 으로 바꾼다. 10.2 재현 행에 '--mute 와 null 장치 --sound 의 --log-hash CSV 가 같음' 을 더한다. 장치 초기화 예외는 GameApp 생성을 감싸 잡거나 null 드라이버로 다시 시도하도록 정한다.
- 처리: 제안대로. 실제로 null 드라이버가 이 MonoGame 판에서 먹는지는 WP7 첫 실행이 확인한다(R21) — 문서 단계에서는 문자열 확인까지다.

#### V4 (중간, 설계) Pipeline 시험 범위
- 자리: architecture.md 10.1 DiabloAssetImporter.Tests Pipeline 행, WP0 완료 기준, 1.4 가져오기 표
- 문제: CI 의 Pipeline 시험은 '시험이 만든 작은 MPQ' 로 돈다. 그런데 거기에 쓰는 표가 실제 Table/*.json 과 Data/maps·tilesets 인지, 시험용 작은 표인지 정해져 있지 않다. 실제 표는 경로 틀 {a}·{d}, frames 범위, frames_are_dirs, 변종 TRN 경로를 담고 있다. 이 실제 표를 끝까지 돌려 보는 일은 이 PC 의 수동 실행(WP0 완료)에서만 일어난다. 그래서 나중에 WP5 가 표에 한 줄을 요청해 고치거나 도구를 고칠 때 생기는 회귀를 CI 가 잡지 못한다. 그 회귀는 사용자 PC 에서 종료 코드 3·4 로 처음 드러난다. 또 합성 MPQ 를 만들 때 쓰는 압축·암호화 플래그도 정하지 않았다. diabdat 는 PKWARE implode, 파일 이름 키 암호화(fix key), 조사 문서가 말한 파형 압축을 쓴다. War3Net 으로 기본값(zlib 또는 무압축)으로 쓰면 원본의 해독 경로는 시험되지 않는다.
- 제안: Pipeline 시험에 '실제 표 전체' 경우를 넣는다. 실제 Table/*.json 이 펼치는 모든 원본 경로에 합성 파일을 만들어 합성 MPQ 에 넣는다: 프레임 수는 정의 JSON 값, TRN 은 256바이트, TIL 은 쓰는 메가타일 번호보다 큰 크기. 실제 Data/maps·tilesets 로 전체 실행이 종료 코드 0 이고, 만든 이름 = 13.5-10 이름 목록인지 본다. 합성 MPQ 는 War3Net 이 쓸 수 있는 범위에서 원본과 같은 플래그(암호화·fix key·PK 압축)로 만든다고 적는다. 못 쓰는 플래그는 '실제 원본 실행에서만 확인' 으로 명시한다. 선택으로 DDR_DIABDAT 이 있을 때만 도는 RealMpq 분류(표의 원본 항목이 모두 열리고 머리가 맞는지, 출력은 임시 폴더)를 둔다.
- 처리: 제안대로.
