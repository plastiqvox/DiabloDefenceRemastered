## 높음

### H1. 입구·보스 등장 좌표가 큰 유닛의 몸 반경보다 경계에 가깝다

- **위치**: 2.4 입구 6곳, 9.5 보스 등장 (60,10), 10.1 "맵 바깥 경계는 모두 벽"
- **문제**: 경계가 벽인데 등장 좌표가 경계에서 10~24px 이다. 해골 왕(반경 30)은 (60,10) 에서 y 방향으로 20px 벽 안에 생기고,
  피의 왕(34)·썩은 거인(26, 남쪽 입구 (765,1000) → 아래 경계까지 24px)·우두머리 시체 덩어리(20×1.3=26)도 같다.
  개별 길찾기(A*)는 시작 칸이 막혀 있으면 길을 못 찾고, 충돌 해소는 유닛을 엉뚱한 방향으로 튕긴다.
  스테이지 마지막 보스가 입구에서 움직이지 않는 결과가 그대로 나온다. 일반 생성 "가장자리에서 16px 안쪽" 도 반경 16 초과 유닛에는 같은 문제.
- **제안**: 둘 중 하나로 정한다.
  (a) 입구를 "맵 밖 시작점 → 맵 안 진입점" 두 점으로 정의하고, 진입점에 닿을 때까지는 경계·충돌을 무시하고 직선으로 걷게 한다(원작 보스의 (-100,-100) 입장과 같은 느낌).
  (b) 모든 등장 좌표는 "경계에서 (그 유닛 반경 + 4) 이상 안쪽" 으로 자동 보정한다는 규칙을 적고, 데이터 검증(13.5)에 넣는다.
  (a) 가 연출이 좋고 계단 입장(9.5)과도 맞는다.

## 중간

### M1. 80px 통로 규칙이 격자 길찾기에서 보스를 못 지나게 한다

- **위치**: 10.1 통로 규칙, 13.5-4·5, 10.4 장애물 배치
- **문제**: 피의 왕 지름 68 에 80px 통로면 여유가 한쪽 6px 이다. 장애물을 몸 반경만큼 부풀려 격자(예: 16px 칸)에 찍으면
  칸 단위로 반올림되어 80px 틈은 막힌 것으로 나온다. 스테이지 2 에는 이런 틈이 여럿 있다:
  `s2_sarc_e`–오른쪽 경계 81px, `s2_wall_e`–`s2_sarc_e` 90px, `s2_arch_n` 서쪽 기둥–`s2_pillar` (575,300) 약 92px, 동쪽 기둥–(965,305) 약 103px.
  보스가 크게 돌아가거나 막힌 쪽에서 비비게 된다. 13.5-5 "길이 있다" 도 어느 몸 크기 기준인지 없다.
- **제안**: 통로 규칙을 "가장 큰 개별 길찾기 유닛 지름 + 격자 2칸 이상(≈ 110px), 아니면 붙임" 으로 올리거나,
  "보스는 이 틈을 못 지나가도 된다, 대신 우회로가 있어야 한다" 로 바꾼다. 검증 13.5-5 는 몸 반경 등급별(14 / 26 / 34)로 따로 돈다고 적는다.

### M2. 적 피해·체력 배율이 쌓이는 순서·방식이 없다

- **위치**: 2.3, 4.2, 8.3 `command_aura`·`war_cry`, 9.1~9.3, 9.4 첫 줄, 2.2 광폭화
- **문제**: 적 피해에 붙는 것이 시간 배율, 정예 ×1.4 / 우두머리 ×1.6, 광폭한, 지휘 오라 +25%, 전투 함성 +30%, 광폭화 ×2 로 여럿인데
  곱하는지 더하는지, 반올림은 언제인지 없다(오라 + 함성이 1.55 인지 1.625 인지). 또 2.3 은 "중간 보스·보스는 **체력** 배율을 받지 않는다",
  9.4 는 "중간 보스는 **시간 배율**을 받지 않는다" 로 피해 배율 적용 여부가 서로 다르다. 보스가 부른 해골, 장판·폭발(자폭, 불타는 접두사, 독 웅덩이) 피해에도 배율이 붙는지 없다.
- **제안**: 한 줄 식으로 정한다. 예: `최종 = round(기본 × 시간배율 × 등급배율(정예/우두머리) × (1 + Σ 버프%) × 광폭화)`, 버프%(오라·함성·접두사)는 더하고 나머지는 곱한다.
  "시간 배율 대상 = 일반·정예·소환된 적, 장판·폭발 포함 / 제외 = 중간 보스·보스 본체의 체력·피해" 로 한 곳에 적는다.

### M3. "초당 생성"이 마리 수인지 무리 수인지 모호하다

- **위치**: 2.4 "일반 생성은 한 번에 1~3마리", 10.3·10.4 구간표 "초당 생성"
- **문제**: 무리 수로 읽으면 실제 생성량이 평균 2배가 되어 레벨 기대치(4.3 "10분에 Lv 22~26")와 동시 최대 수 도달 시점이 크게 달라진다.
  마리 수로 계산하면 스테이지 1 10분 동안 약 1,740마리 + 이벤트 → 처치 경험치로 Lv 23~24 쯤이라 기대치와 맞는다. 즉 의도는 마리 수로 보인다.
  또 동시 최대 수를 넘었을 때 "미룬다" 가 밀린 수를 쌓아 두었다가 한꺼번에 내보내는지, 버리는지도 없다.
- **제안**: "초당 생성 = 마리 수. 누적기(accumulator)가 1~3 이상 차면 그만큼 한 무리로 낸다" 로 적는다.
  최대 수 초과 시는 "누적기를 최대 3 에서 멈춤(밀린 것은 버림)" 처럼 한 줄로 정한다.

### M4. 전체 상한 300 을 넘는 분열·소환·호위를 어떻게 하는지 없다

- **위치**: 2.3 "전체 상한 300", 8.3 `split_on_death`·`command_aura` 호위, 9.4 시체 부르기·전투 함성 소환, 9.5 해골 소환
- **문제**: 스테이지 2 후반 구간 최대 250 + 이벤트(시체 덩어리 8 → 24마리, 포위 16 등) + 보스 소환으로 300 에 닿는다.
  분열·소환이 상한에 걸려 조용히 안 나오면 패턴이 사라지고(중간 보스 "시체 부르기" 가 빈손), 무시하면 성능 상한이 깨진다.
- **제안**: 우선순위를 정한다. 예: "보스·중간 보스 소환과 분열은 상한 무시(대신 상한 + 60 까지만), 일반 생성 → 이벤트 → 소환 순으로 먼저 막는다".
  또는 상한에 걸리면 가장 먼(화면 밖) 일반 적을 지우고 자리를 낸다. 어느 쪽이든 한 줄로 적는다.

### M5. 주인공과 적의 몸 충돌 규칙이 없다

- **위치**: 1 기둥 1 "포위 뚫기", 8.1 분리(steering), 4.1 몸 반경 14
- **문제**: 적끼리는 분리로 밀어낸다고 했지만 주인공–적 사이는 없다. 적이 주인공을 막는지(갇힐 수 있음), 주인공이 적을 밀어내는지,
  서로 통과하는지에 따라 게임 느낌과 난이도가 완전히 바뀐다. "포위 뚫기" 가 실력이라는 기둥과 직결된다.
- **제안**: 예: "적은 주인공을 단단한 원으로 취급해 피해 간다(주인공 질량 무한). 주인공은 적과 겹치면 적 쪽만 밀린다. 단 적이 주인공 둘레를 빈틈없이 두르면 주인공이 갇힐 수 있다(의도)" 처럼 정한다.
  갇힘을 원치 않으면 "주인공은 적을 천천히 밀고 지나간다(초당 N px)" 를 적는다.

### M6. 투사체·구체의 충돌 반경이 어디에도 없다

- **위치**: 5.3~5.8, 8.3 `shoot_arrow`·`cast_bolt`, 9.5 파이어볼 부채·화염 고리
- **문제**: 매직 미사일·파이어볼 직격·화살·비전 구체·적 화살·마법탄의 맞음 판정 크기가 없다. 그림 배율(×0.45~0.8)에서 추측하게 된다.
  맞는 판정은 체감 난이도(특히 적 투사체 피하기)에 직접 걸린다.
- **제안**: 각 투사체에 `반경` 값을 준다(예: 매직 미사일 6, 파이어볼 8, 화살 4, 비전 구체 12, 적 화살 4, 적 마법탄 7). 아래 M8 의 투사체 정의에 항목으로 넣는다.

### M7. 패시브가 4.1 능력치 키로 표현되지 않는다

- **위치**: 4.1 능력치 키, 6절 표와 "패시브 효과는 4.1 의 능력치 키를 더하는 것뿐"
- **문제**: `field_runner` 는 이동 **+8%**·획득 반경 **+20%** 인데 4.1 키 `move_speed`(px/s)·`pickup_radius`(px) 는 절댓값이다.
  `stone_skin` 의 "넉백 받는 거리 −10%" 는 주인공 쪽 키가 없다. `vitality` 의 "얻는 순간 같은 양 회복" 은 능력치 더하기가 아니다. E 의 `greed`(금화 +20%)도 키가 없다.
  "키를 더하는 것뿐" 이라는 데이터 원칙과 실제 표가 어긋나 구현자가 특례 코드를 넣게 된다.
- **제안**: 키를 늘린다: `move_pct`, `pickup_pct`, `knockback_taken_pct`, `gold_pct`. 퍼센트는 "기본값 × (1 + Σ%)" 로 더해서 적용한다고 적는다.
  `vitality` 회복은 패시브 정의의 `on_acquire` 효과(체력 회복) 항목으로 따로 둔다.

### M8. 이펙트·투사체 정의가 없어 "마법 이펙트 확장"(사용자 요구 6)이 무기·행동 안에 흩어진다

- **위치**: 13.1 정의 종류, 5.2 그림 열, 8.3 원거리 부품, 9.4·9.5 보스 패턴, 11.1, 12.6
- **문제**: brief 2절 요구 6 은 "스테이지, 적, **마법 이펙트**, 스킬" 확장이다. 지금은 이펙트(폭발, 장판, 빛 기둥, 번쩍임)와 투사체(시트·색조·크기·속도·유도·수명)가
  무기 정의·행동 매개변수·보스 패턴 글에 각각 박혀 있다. `FireBallExplosion` 색조만 다른 폭발이 파이어볼·자폭·불타는 접두사·불타는 땅·연옥불에 다섯 번 따로 쓰인다.
- **제안**: 13.1 에 두 정의를 더한다.
  - `effect`: 시트, 프레임 범위, 반복 여부, 프레임 시간, 색조, 크기, 혼합(일반/가산), 빛(색·반경·시간), 화면 흔들림.
  - `projectile`: 그림(시트·색조·크기·방향 수), 반경, 속도, 유도 회전율, 수명/사거리, 장애물 막힘 여부, 관통, 맞음 `effect` ID, 폭발(반경·피해 배율·`effect` ID).
  무기·적 행동·보스 패턴·접두사는 이 ID 를 참조만 한다. 그러면 "새 마법 이펙트 = effect 정의 1개" 가 된다.

### M9. 보스·중간 보스 패턴이 13.3 행동 부품으로 표현되지 않는다

- **위치**: 9.4, 9.5 패턴 표, 13.1 `enemy`, 13.3
- **문제**: 파이어볼 부채, 화염 고리(사방 발사), 불타는 땅(예고 후 지점 폭발), 돌진 베기, 내려치기(근접 + 넉백 + 흔들림), HP 문턱 1회 소환, 페이즈 전환이
  13.3 목록(`summon`, `ground_hazard`, `boss_phase` 등)에 대응 부품이 없거나 매개변수 모양이 없다. 13.1 `enemy` 에도 패턴 목록·페이즈·이동 방식(플로우/A*/직선)·
  면역(넉백·둔화)·보스 체력 막대·시간 배율 적용 여부 항목이 없다. 그대로면 보스 4종이 각각 코드로 만들어지고 "정의로 늘어난다" 가 보스에서 깨진다.
- **제안**: 보스 패턴을 하나의 틀로 적는다: `패턴 = { 조건(거리 범위 / 쿨 / HP 문턱 1회), 애니메이션(시트·트리거 프레임), 예고(effect·시간), 동작 부품 ID + 매개변수 }`,
  `페이즈 = { HP 문턱, 패턴 목록 교체·수치 덮어쓰기, 전환 연출 }`. 부품은 `melee_slam`, `projectile_spread`(부채·고리 = 각도 범위와 발 수), `telegraphed_blast`, `dash`, `summon` 정도로 묶인다.
  `enemy` 정의에 `movement`(flow/astar/direct), `immunities`, `show_boss_bar`, `time_scaling` 항목을 더한다.

### M10. 맵 정의가 스테이지 안에 섞여 있다

- **위치**: 10.1 공통 장애물 5개·입구 6곳·시작 위치·질감 원본, 13.1 `stage`
- **문제**: 두 스테이지가 같은 `Dungeon1` 을 쓰는데 공통 장애물(덤불·석관·우물·받침), 입구, 시작 위치, 빛나는 자리, 질감 원본 영역이 13.1 어느 정의에도 자리가 없다.
  스테이지마다 복사하면 좌표를 디버그 보기로 고칠 때(열린 질문 7) 한쪽만 고쳐지는 일이 생긴다. 보스 등장 좌표("왼쪽 위 계단")도 이벤트 글에만 있다.
- **제안**: `map` 정의를 둔다: 그림, 미니맵, 고정 충돌 모양(그리지 않음), 입구 목록(ID·좌표, H1 의 진입점 포함), 시작 위치, 기준점(빛나는 자리), 장애물 질감 원본 영역.
  `stage` 는 `map` ID 를 참조하고 추가 장애물·조명·시간표만 가진다. 이벤트의 위치는 입구 ID 로 적는다(`entry:stairs_nw`).

### M11. 무기 정의에 조준 규칙·기본 비행 수치 자리가 없다

- **위치**: 5.2 "조준" 열, 5.3~5.8 표 위 문장(속도·수명·회전율·사거리·넉백), 13.1 `weapon`
- **문제**: 조준 규칙(가까운 적 / 반경 안 무작위 / 바라보는 방향 / 밀집 지점 / 없음)이 표 열에는 있는데 정의 항목에는 없다.
  레벨 표 밖 고정값(매직 미사일 회전 360°/s·수명 3s, 파이어볼 속도 380·사거리 450, 뼈 화살 수명 0.9s)도 어느 항목인지 없다.
  또 `projectile_count`·`area_pct`·`duration_pct` 가 패턴마다 무엇에 붙는지(비전 구체 개수? 장판 개수? 부채 발 수?) 정해져 있지 않다(MVP 패시브엔 없지만 진화 `inferno` 장판 반경 등에 걸림).
- **제안**: `weapon` 에 `targeting`(ID + 반경), `base`(레벨 무관 수치), 레벨 표 열 이름 = 발사 패턴이 읽는 키 이름으로 고정한다.
  패턴별로 "발 수 키 / 범위 키 / 지속 키" 를 13.2 에 한 줄씩 적는다. 진화 무기는 `base_weapon` + 덮어쓸 수치 + 추가 효과(`on_explode: hellfire_pool 정의`)로 적는다.

### M12. 정예 무리의 "종류"를 고르는 규칙이 없다

### M13. 적 태그가 표에 없다

### M14. 흰 실루엣·가려진 주인공 윤곽선·그림자 흐림은 셰이더 없이 바로 안 된다

- **위치**: 12.6 맞을 때 번쩍임 "흰색 실루엣(같은 프레임을 흰색 가산으로)", 10.2 "가려진 주인공 윤곽선", 그림자 "가장자리 4px 흐리게"
- **문제**: 프레임을 흰색으로 가산하면 그림 자기 색이 더해질 뿐 흰 실루엣이 되지 않는다. 윤곽선·흐림도 셰이더나 미리 만든 텍스처가 필요하다.
  brief 3절은 MGCB 를 쓰지 않는다고 정했으므로 `.fx` 셰이더는 따로 컴파일 단계를 들여야 한다. 그림 시트 전체가 이미 약 206MB(RGBA 기준)라
  유닛 시트마다 흰 마스크 사본을 만들면 약 170MB 가 더 든다.
- **제안**: 기획 쪽 표현을 "밝게 번쩍임" 으로 낮추고 방법은 설계에 맡긴다고 적는다. 설계 쪽 기본안: 번쩍임 = 같은 프레임 가산 2회(밝게), 윤곽선 = 주인공 시트만 CPU 로 실루엣 사본을 만들어 α0.5 로 위에 그림,
  그림자·장애물 = 스테이지 시작 때 CPU 로 텍스처를 미리 구움(흐림 포함). 셰이더를 쓰기로 하면 그때 설계에서 정한다.

### M15. 시트마다 발 위치(기준점)가 없다

- **위치**: 13.1 `sprite`, 8.1, 10.2 "발밑 y 로 정렬"
- **문제**: 실제 그림을 보면 96×96 해골은 발이 프레임 아래쪽(대략 y 88), 160×160 해골 왕은 y 150 근처다. 프레임 가운데를 위치로 쓰면
  충돌 원이 몸 가운데로 올라가고, y 정렬·그림자·발밑 원(오라, 아군 표시)이 어긋난다. 크기 배율(×0.65~1.9)이 붙으면 더 벌어진다.
- **제안**: `sprite` 에 `origin`(발 위치, 프레임 안 픽셀) 항목을 더한다. 값은 구현 때 디버그 보기로 시트마다 맞춘다(열린 질문 7 과 같이).
  크기 배율은 이 기준점을 중심으로 건다고 적는다.

### M16. MVP 가 한 번에 만들기에 크다

- **위치**: 14.1
- **문제**: 무기 6 + 진화 2, 패시브 6, 몬스터 11, 정예·우두머리·접두사 3, 중간 보스 2(패턴 3씩), 보스 2(패턴 4 + 3), 스테이지 2(이벤트 각 10개 남짓),

- **제안**: 세 단계로 나눈다(내용은 그대로, 순서만).
  1. **세로 조각**: 스테이지 1 맵·장애물·조명, 매직 미사일·파이어볼·비전 구체, 패시브 3, 해골·좀비·궁수·불타는 해골·굶주린 시체, 레벨업·결과, `--autoplay`·`--capture`.

  3. **스테이지 2**: 망령·주술사·타락한 검사, 기사 대장, 피의 왕, 스테이지 2 장애물·조명·시간표.

### M17. 검증용 실행 옵션이 보스·후반 검증에 부족하다

- **위치**: 15절, brief 7절
- **문제**: 보스는 10:00·12:00 에 나오고 자동 조작이 그때까지 살아 있어야 한다. 검증 한 번에 10분 넘게 걸리고, 자동 조작이 죽으면 보스를 아예 못 본다.
  스테이지 선택·타이틀 메뉴를 자동 조작이 어떻게 지나는지도 없다.
- **제안**: 개발 옵션을 더 적는다: `--stage <id>`(타이틀 건너뛰고 바로 시작), `--start-at <mm:ss>`(시간표를 그 시각부터, 그 시각까지의 이벤트는 건너뜀),

### M18. 데이터 검증 규칙 6 이 그림 파일을 읽는다 — 저장소에는 그림이 없다

- **위치**: 13.5-6, brief 1절(그림은 git 에 넣지 않음)
- **문제**: "시트 크기 = 프레임 크기 × 방향/프레임 수" 를 테스트하려면 PNG 를 열어야 하는데, 클론 직후·CI 에는 `Assets/` 가 비어 있다. 테스트가 늘 실패하거나 늘 건너뛴다.
- **제안**: `sprite` 정의에 시트 크기를 같이 적고, 테스트는 "정의끼리 맞는지"(항상 실행) + "실제 PNG 와 맞는지"(그림이 있을 때만, 없으면 건너뜀 표시)로 나눈다.
  `FireBall` 처럼 나머지 픽셀이 남는 시트를 위해 "남는 픽셀 허용" 표시를 둔다.

### L12. 장애물 정의가 인스턴스 덮어쓰기·복합 모양을 담지 못한다
- **위치**: 10.2 종류 표, 10.3 `s1_wall_w` 높이 30(종류 기본 36), 10.4 `s2_arch_n`, 13.1 `obstacle_kind`
- **문제·제안**: 배치에서 높이를 바꾸는 경우와 아치(충돌 2개 + 그림만 있는 상인방)가 있다. 배치 항목에 `height` 덮어쓰기, 종류에 `parts`(충돌 모양 여러 개 + 그림 전용 부분), 그리고 충돌만 있는 종류(`collision_only`, 덤불·석관·우물)를 둔다.

### L13. 같은 텍스처를 여러 번 바꿔 그려 그리기 호출이 늘 수 있다
- **위치**: 8.1 발광, 10.2 y 정렬, 2.3 상한 300, 8.1 시체 150
- **문제**: 유닛 300 + 시체 150 을 발밑 y 로 정렬하면 시트(약 20장)가 번갈아 나와 텍스처가 바뀔 때마다 그리기 호출이 끊긴다. 발광을 가산 혼합 상태로 그리면 혼합 상태 전환으로 또 끊긴다. 최악 1,000회 안팎이라 막히지는 않지만 낭비다.
- **제안**: 기획 쪽에선 지금 수치로 충분하다. 설계 메모로: premultiplied 에서 "정점 색 알파 0" 으로 그리면 같은 AlphaBlend 상태 안에서 가산이 되어 발광이 배치를 끊지 않는다.
  빛(10.5)은 동시 개수 상한(예: 64)을, 아군·적 투사체도 안전 상한(예: 주인공 쪽 400, 적 쪽 200)을 적어 둔다. 지금 계산으로 투사체는 수십 개 수준이라 위험 낮음.

### L14. 커서 파일은 MonoGame 이 바로 못 읽는다
- **위치**: 3절 "마우스 커서는 `DIInop.cur`"
- **문제·제안**: `DIInop.cur` 는 32×32 8비트 팔레트 BMP 커서(핫스팟 (0,0))라 `Texture2D.FromFile` 로 못 연다. `tools/import-assets.ps1` 에서 PNG + 핫스팟으로 바꿔 두거나 작은 해석기를 둔다(설계에서 정함). 기획서는 "핫스팟 (0,0)" 만 적어 두면 된다.

### L15. 시트에 그림자가 구워져 있다
- **위치**: 8.1 색조·발광, 12.6 번쩍임
- **문제·제안**: 유닛 시트 발밑에 어두운 그림자가 그림으로 들어 있어 색조·발광·번쩍임·투명도(망령 α0.55)가 그림자에도 걸린다. 큰 문제는 아니지만 "그림자도 같이 물든다(허용)" 로 적어 두면 구현·검증 때 버그로 오해하지 않는다.
  또 해골 원본 색이 연분홍이라 금색·주황 색조 결과가 기대와 다를 수 있다 — 첫 구현 때 색조 미리보기 화면으로 확인한다.

### L16. 몬스터 다양화를 데이터만으로 하나 더 증명하면 좋다
- **위치**: 8.4 `skeleton_mage`, 13.6 예시
- **문제·제안**: 사용자 요구 8 은 MVP 10종으로 충족한다. 다만 "새 적 = 정의 1개" 를 실제로 보여 주는 예가 MVP 에 없다. `skeleton_mage`(= `kite` + `shoot_projectile`, 새 코드 없음)를
  2단계(M16) 끝에 넣으면 확장 구조를 검증하는 시험이 된다. `plague_zombie`(`chase_melee` + `ground_hazard` 사망 시)도 기존 부품만 쓴다.

### L17. 레벨업 "초반 보장" 표현
- **위치**: 4.4 "Lv 2, Lv 3 선택에는"
- **문제·제안**: "Lv 2 가 되었을 때, Lv 3 가 되었을 때 뜨는 선택" 으로 적어 모호함을 없앤다.

### L18. 중간 보스와 최종 보스가 함께 있을 때 체력 막대
- **위치**: 12.1 위 가운데
- **문제·제안**: 중간 보스를 안 잡고 버티면 보스 등장 때 둘이 같이 있다. 막대를 둘 다 보일지(위아래), 보스만 보일지 적는다.
