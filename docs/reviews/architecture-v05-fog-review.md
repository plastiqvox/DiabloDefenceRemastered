## 제안과 다르게 반영한 것

- **I2·V1 생성 질의**: 제안은 `HiddenForSpawn(pos) = !Enabled || !IsVisible(pos)`(또는 `Enabled && IsVisible` 이면 버림)으로 생성 쪽 질의를 따로 두는 것이었다.
  같은 묶음의 기획 지적 P3 가 규칙 자체를 빼자고 했고(기획 쪽 권장 (가)) 설계도 같은 판단이라, 규칙을 뺐다 — 뒤집힘이 생길 자리가 없어진다.
  기획 v0.6.1 도 (가)로 뺐다. 비슷한 규칙을 다시 넣을 때 쓸 형과 기본값(꺼진 월드 = 아무것도 안 버림)은 설계 6.12 에 남겼다. V1 의 "13.5-15 에 반경 > 0" 은 P5 의 380 하한으로 합쳤다.
- **I3 벽 두께 규칙**: 두 안(같은 메가타일 / 4방향 이웃) 중 **같은 메가타일**을 골랐다. MVP·스테이지 2 의 두 줄 벽은 모두 메가타일 한 장(2×2) 안에서 두 줄이고, 메가타일 규칙은 한 번만 적용돼 긴 벽을 타고 퍼지지 않는다.
  대상은 걷기·시야를 둘 다 막는 `W`·`X` 만이다 — 시야만 막는 `L`·`M`(걸을 수 있음)에 넣으면 그 칸에 선 원거리 적이 옆 칸 덕에 "보임" 이 될 수 있다.
  지적 둘째 부분(숨은 벽 그림이 보이는 칸 위로 솟아 max(1, 0) = 1)은 두 줄 벽이면 이 규칙으로 없어진다. 서로 다른 벽 두 개가 겹치는 배치는 스테이지 1 에 없어 남은 한계로 적고,
  생기면 벽 항목만 "지우기 + 더하기" 두 번 그리기로 자기 칸 값으로 덮어쓰는 길을 7.10 에 적었다.
- **I6 `sight.json` 소유**: 키를 두 파일로 나누지 않았다(기획이 흐림 띠와 또렷이 보임 경계를 같은 40 으로 묶었으므로). 대신 키별 소유를 적었다 — 시뮬레이션 값 넷은 메인 세션이 WP4 와 합의해 바꾸고 `Scenario`·13.5-15 를 다시 돌린다.
  제안의 두 길(키별 소유 / WP5 완료 기준에 다시 돌림)을 둘 다 넣었다.
- **I9 렌더 최악 측정**: 제안은 "안개를 켜고 적을 시야 안에 채운 장면" 또는 "`--reveal` 과 안개 두 번" 이었다. 새 채우기 옵션을 두지 않고 두 번째 길(같은 명령을 `--reveal` 과 안개 켬으로 재고 `fog_ms` 열을 더해 최악을 추정)로 했다.
- **V4 자폭·근접**: 두 제안(점화 중 늘 보임 / 반경 60 예고 원) 중 **점화 중 `Visual.ForceShown`** 을 골랐다 — 기획의 예고가 이미 번쩍임이라 원을 더 그리지 않는다.
  근접은 오류로 막지 않고 적마다 `TouchReach`(근접 사거리 여분 + 타격 여유 10, 최소 `touch_margin`)로 닿은 거리를 늘렸다 — 13.5-13 이 근접 단일 사거리를 + 50 까지 허용하므로 데이터를 막지 않는다.
- **V5·P1 떨림**: V5 의 "254 − 8 안에서만 물러남" 히스테리시스 대신, 기획 v0.6.1(같은 P1 을 기획 쪽에서 반영)이 정한 `kite` **띠 당기기**를 담았다 —
  L = 그 적 방향으로 또렷이 보이는 가장 먼 거리(벽 제외, `VisibilityField.ClearReach`), 쓰는 띠 = 최대' = min(최대, L − 10), 최소' = min(최소, 최대' − 40).
  띠 폭이 늘 40 이상이라 히스테리시스와 같은 효과가 나고, 몸 위 끝까지 보는 화면 조건에서도 위쪽 궁수가 쏠 자리가 생긴다. P1 의 "13.5-15 에 띠 최소 ≤ 위아래 한계" 검사는 이 규칙으로 필요 없어 두지 않았다.
  (설계가 처음 적은 "경계 안쪽 10px 에서 물러남만 멈춤" 은 기획 v0.6.1 이 나온 뒤 기획 규칙으로 바꿨다 — 기획이 리뷰 안에 띠 폭 40 을 붙였다.)
- **P1 몸 높이 자리**: 기획은 "그림 묶음 값, 이름·자리는 설계" 로 넘겼다. 그림 묶음 `body_height`(필수, px, 크기 배율 1 기준) → 생성 때 `Enemy.BodyTop` = `body_height` × 최종 크기로 했다. 설계가 처음 적은 "걷기 클립 `origin.y` × 크기" 는 칸 위 끝까지라 그림보다 커서 버렸다.
- **V6 고정 장면**: 제안의 `--hero-at` + `--freeze-ai` + 정해 둔 적 배치 대신 `--preview fog`(WP5 미리보기 장면 여섯 개, 앱 k 초 = 장면 k)로 했다 — 기존 `--preview` 처럼 배치를 코드에 고정하면 스테이지 시각·자동 조작과 무관하다.
  그래서 "스테이지 시각 기준 캡처 옵션" 은 두지 않았다. 150초 행진 캡처(문 틈 궁수)는 장면 ② 로 옮겼다. 캡처마다 `FOG` 로그 줄과 빛 지도 PNG(`_light.png`)를 남겨 I1 의 값 대조도 같은 장면에서 한다.

## 지적 원문

### 구현 담당

#### I1 (높음, 설계) 회색 최댓값 혼합
- 자리: 7.10 FogRT 3·4단계, MemRT 2단계, 7.7 ④ 유닛 최소 밝기
- 문제: "기둥·대상 모양을 값 g 의 회색으로 최댓값 혼합" 은 셰이더 없는 SpriteBatch 로는 그렇게 되지 않는다. SpriteEffect 의 결과는 텍스처 색 × 틴트이고, Max 혼합은 혼합 계수를 무시한다. 그래서 FogRT 에 들어가는 값이 g 가 아니라 벽·적 그림의 색 × g 가 된다.
  그 결과 보이는 뒷벽의 윗부분이 검정 대신 색² 밝기로 어둡게 남는다(R28 에서 막으려던 바로 그 결과). 시야 밖에서 늘 그리는 보스·닿은 적도 색² 로 어두워진다. 기존 7.7 ④ 도 같은 문제가 있다.
  어두운 픽셀에서 하한이 0.6 보다 낮아져서, 사용자 결정 A 의 판독성 규칙(시야 안 0.6)이 표시 없이 지켜지지 않는다. 캡처를 대충 보면 통과할 수 있는 오동작이다.
- 제안: 값을 색 채널이 아니라 알파 채널에 담는 방법으로 7.10·7.7 을 고쳐 적는다. ① 모양: ColorWriteChannels = Alpha, AlphaBlendFunction = Max, 틴트 = (255,255,255,g) → 결과 알파 = 그림 알파 × g.
  ② 땅 투영: SightTex·ExploredTex 도 알파에 값을 둔다(LinearClamp). ③ 합치기: LightRT ← LightRT × FogRT.a 는 ColorSourceBlend = Zero, ColorDestinationBlend = SourceAlpha 로 한다.
  MemRT 는 색을 흰색으로 지우고 알파만 쓴 뒤 (1−V) 를 InverseSourceAlpha 로 곱하고, 틴트 M 과 SourceAlpha/One 가산으로 더한다.
  ④ 최소 밝기: 보조 RT 에 LightRT 를 복사 → 전체 화면에 m 과 Max → 대상 모양을 알파에 씀 → SourceAlpha/InverseSourceAlpha 로 LightRT 에 덮는다.
  10.1·10.2 에는 "어두운 그림 픽셀도 하한 ≥ m" 을 픽셀로 확인하는 항목(미리보기 캡처의 값 대조)을 더한다.
- 처리: 제안대로. 혼합 상태 아홉 개를 7.10 `FogBlend` 표로 모으고 7.7 ④ 는 `MemRT` 를 보조 RT 로 다시 쓴다(렌더 타깃을 늘리지 않음). 모양 알파에 안개 알파 × 그림 알파를 써 P2 도 같이 고쳤다.
  픽셀 확인은 그래픽이 필요해 10.1(Core 만)이 아니라 10.2 "안개 고정 장면" 에 두었다 — 빛 지도 PNG 에서 대상 모양 안 ≥ m, 보이는 벽 그림 자리 = `--reveal` 의 같은 자리 값.

- 처리: 설계 쪽 제안대로, 값은 기획 v0.6.1 — `IsClearlyVisible(pos, top)`(발과 몸 위 끝), 그림 묶음 `body_height` → `Enemy.BodyTop`(× 최종 크기), `kite` 띠 당기기(`ClearReach`), 정위 궁수 시험. 13.5-15 검사는 규칙 변경으로 필요 없음. 위 "제안과 다르게".

#### P2 (중간, 설계) 최소 밝기와 흐림 띠 실루엣
- 자리: architecture 7.7 유닛 최소 밝기 ④ — "경계 흐림 띠의 대상은 그림 알파가 이미 줄어 있어 m 을 그대로 쓴다"
- 문제: 최소 밝기 덧그림은 LightRT 에 대상 실루엣을 (m,m,m) 최댓값으로 찍고, 이 LightRT 가 WorldRT 전체에 곱해진다. 대상을 알파 a 로 그리면 그 실루엣 안 픽셀은 "바닥 × (1 − a) + 적 × a" 다. 그래서 실루엣 안의 바닥까지 밝기 m(0.6)을 받는다.
  흐림 띠(R − 40 … R)와 0.15s 페이드 중인 칸에서는 주변 땅이 V·L + 기억 ≈ 0.2~0.4 다. 적이 거의 투명할 때(a ≈ 0.05)부터 둘레보다 2~3배 밝은 "바닥 모양 실루엣" 이 먼저 드러난다.
  기획 10.7 의 부드러운 경계와 어둠 연출(원작 느낌)이 깨지고, 적이 시야 경계에서 유령처럼 튀어나와 보인다. 4단계 FogRT 덧그림은 알파를 곱하는데 ④ 는 곱하지 않아 둘이 어긋난다. phase_through 알파 0.3 에도 같은 일이 있었지만, 안개 때문에 모든 적이 매번 겪게 된다.
- 제안: ④ 의 덧그림 색을 하한 × 안개 알파(m·α, 최댓값 혼합)로 둔다. 늘 보이는 보스·닿은 적은 α = 1 이라 그대로다. phase_through 같은 그림 알파도 같이 곱할지는 설계가 정한다. 10.2 "안개" 캡처 판정 문장에 "흐림 띠의 적 둘레에 밝은 바닥 실루엣이 없음" 을 더한다.
- 처리: I1 의 새 ④(모양을 알파에, max(L, m)·a + L·(1 − a))에서 a = 안개 알파 × 그림 알파 — 그림 알파도 곱한다. 10.2 장면 ④ 에 빛 값 기준과 함께 더함.

#### P3 (낮음, 둘 다) 보이는 생성 후보 버림
- 자리: gdd 2.4 위치 조건·10.7 생성 / architecture 6.12 일반 생성 자리·10.1 Director
- 문제: "보이는 생성 후보 버림" 은 화면에 아무 차이를 만들지 않는다. 생성 띠는 늘 화면 밖(화면 사각형 바깥 40~200px)이라 거기 선 적은 안개와 무관하게 안 보인다. 위아래에서 오는 적은 화면 위 가장자리(270 < R − 40)에서 이미 시야 안이라 어디서 생기든 빛 속에서 들어온다.
  그래서 "적은 늘 어둠에서 나온다" 는 근거가 맞지 않는다. 실제 효과는 생성 분포가 정위·정아래에서 양옆·모서리로 13.5%/6.6% 옮겨 가는 것과, 모서리 주인공일 때 입구 대체(R23)가 조금 늘어나는 것뿐이다. WP4 코드·시험 하나가 그 값을 치른다.
- 제안: 둘 중 하나를 고른다. (가) 규칙을 뺀다: 기획 2.4·10.7·14, 설계 6.12·10.1 Director·13.8 의 해당 줄을 지운다. (나) 남긴다면 근거를 "생성 분포를 양옆(어둠에서 들어오는 쪽)으로 미는 것" 으로 바꿔 적는다. 기획 쪽 권장은 (가). 시야 공정성은 원거리·돌진 조건이 이미 지킨다.
- 처리: (가)(기획 v0.6.1 도 (가)). 설계 쪽 줄을 지웠다(13.8 표는 그 시점 기록이라 두고 13.9 에 뺐다고 적음). 비슷한 규칙을 다시 넣으면 I2 의 형(꺼진 월드 = 아무것도 안 버림)으로.

#### P4 (낮음, 둘 다) `--reveal` 과 저장 보호
- 자리: architecture 9절 --reveal 행·사용자 데이터 보호 / gdd 15절
- 문제: 설계는 --reveal 을 개발 옵션 판정(저장 보호)에 넣지 않았다. 기획 15절은 --reveal 을 개발 실행 옵션 표에 두고 "개발 옵션 실행은 사용자 저장 파일을 읽지도 쓰지도 않는다" 고 했다. --reveal 만 주고 보통 플레이를 하면 안개 없는 판의 해금·기록이 사용자 저장에 남는다. --god 도 같은 틈이 이미 있다.

- 처리: 첫 길(다섯 옵션 모두).

#### P5 (낮음, 둘 다) 13.5-15 하한

- 문제: 기획 10.5-3 은 빛 반경을 380~480 에서 고르라 했는데, 검사 13.5-15 는 "≤ 480" 과 "≥ 원거리 최대 + 60" 만 본다. 원거리 적이 없는 스테이지(E 후보)는 하한이 없어 R 이 아주 작아도 통과한다. hero_light 를 빠뜨려 반경이 0 이면 설계 VisibilityField.Enabled 가 거짓이 되어 안개와 시야 조건이 조용히 꺼진다.
